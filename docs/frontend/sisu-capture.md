# Sisu import

The Sisu import validates a downloaded capture or a supported plan PDF, prepares an import profile and places the pending hierarchy into the structure of studies.

## The capture boundary and the pending placement

`web/src/features/structure/sisu.ts` holds the capture boundary and the pending placement.

`validateSisuPlan(value)` is the recursive check of one capture hierarchy. It requires a non-array object, a nonempty programme array of module objects, the exact `course` and `module` discriminants, nullable nonempty string identities, the required nullable module `versionId`, a nonempty course code and name, a nullable module code, a boolean completion, and arrays of children, and it rejects two non-null top-level programme identities that agree because a programme has one top-level place. An unknown field is discarded, a repeated course occurrence is accepted, and every failure raises `Invalid Sisu plan file`.

`parseSisuCapture(value)` is the boundary of one downloaded capture. It requires a nonempty `markup` string, a module lookup record of group-id lists keyed by the status cell identity the page shows, and a course lookup record of `{ code, groupId }` hits keyed by the displayed code.

The markup is parsed with `DOMParser` as data and is never inserted into the document or evaluated, and the identity of every module and course comes from the lookup records alone: a course hit is matched on its exact code and its group ids are de-duplicated, and a module's list of group ids is de-duplicated, so one sole identity is used and zero or several identities leave the item unresolved.

The hierarchy is read from the module element that holds each row of the plan tree: the own name, the own code, the own status identity that supplies the exact version id when the group resolves, and the own direct module and course rows in document order.

A module with the graduation flag carries a degree header, and a top-level header with no graduation flag, no grouping title and no module information control is the education container, whose direct degree rows become the top-level programmes in their displayed order. A capture with no readable programme raises `Invalid Sisu plan file`.

`prepareSisuProfile(capture, name, language)` builds the profile one import creates: the language of the interface at confirmation, one ordered distinct selected identity per non-null captured course, a completion for every identity that any occurrence captured as completed, one exact version pair per resolved captured module, the resolved top-level programme identities in capture order, and one independent copy of the hierarchy in `pendingSisuImport`. Two different exact ids for one group raise `Sisu plan selects two versions of a module`, and the call reads no storage and sends no request. Choices, places, placed identities and the card order start empty. `BrowserStore.importProfile` then applies the shared trimmed-name, empty-name and duplicate-name rules.

`sisuImportBlocked(state)` answers whether one waiting capture sits beside saved structure edits. It is true exactly when `pendingSisuImport` is not null and one of the choice keys, the two placement maps, `placedCourseIds` or a nonempty `courseOrder` holds an entry. A choice entry with an empty list counts, and a placement counts even when its target is `null`, because both are saved edits. Programme identities, version selections and the shared course sets alone do not count, because a prepared capture fills them without an edit.

`resolveSisuImport(state, content, unavailable)` returns `null` while no capture waits, while `sisuImportBlocked` is true, and while a read the capture needs has not settled: every resolved module identity of the capture, at any depth, needs a report or a recorded unavailable module, and every selected identity needs a summary or a recorded unavailable course. `captureModuleIds(capture)` returns that module list in capture order, and the pane reads it while the record is pending. Otherwise it returns one `StructureChange` and the issues of the placement, and it writes nothing.

- The available programmes are the captured ones whose report the content holds, and they are written in capture order. Each scope reads `officialHomes` again, so a module placed above it contributes its own official homes to the suppression below. A programme whose identity is unresolved or whose report is unavailable is named as an issue, its representable descendant courses are placed in the `u` bucket, and no education wrapper or invented group id is created.
- One walk per programme starts at the `programmeKey(groupId)` node of the forest. For a captured direct course or module it searches the parent's entries and every option through transparent and choice nodes, and it stops at the boundary of a nested module. A match of a course or a module contributes its choice path, selected through `nextChoices` only when a step is absent, and records the matched entry's `origin.ownerKey` as its place. The walk descends into a matched module's node for its captured children.
- A representable captured course outside the parent's official alternatives is placed on the parent module node with `placeCourse`, so it draws the added outline. An unresolved identity is named and left out, and a captured course outside the hydrated summaries is named, left out of the placed identities and removed from both course sets.
- A module item whose identity and code are both null is matched by its exact Finnish or English official name among the direct child modules of the readable parent scope, using the same traversal. One match is placed and its captured children are walked inside it. No match reports `no_official_match`, several report `ambiguous_official_match`, and either outcome leaves the item out with the same loose-descendant handling. A module item with a code but no identity keeps the generic `unresolved` outcome.
- A captured module outside the parent's official tree joins that parent through a `modulePlacements` entry, and the walk descends into the node `buildStructure(report, "<parentKey>/m:<id>")` builds from its own report, so its captured children are placed inside it and its uncaptured official content is suppressed. A module with no report at all is named as an issue, and its representable descendant courses are placed in the `u` bucket rather than a branch of that programme.
- Every official identity of one parent scope that the capture does not hold there is suppressed through a `null` placement, so a default projection cannot select content the capture does not hold. A captured course or module keeps its matched owning key, so a captured deselection or move is preserved rather than turned into a second card, and a matched module whose placement record exists keeps that recorded place rather than a suppression.
- An identity that one parent scope offers twice, a captured sibling module that the scope offers twice, a choice path step into an already chosen single option, and a captured sibling module whose identity repeats raise `Sisu choice is ambiguous` and the caller writes nothing.
- The returned change holds the next structure with an empty card order, the unavailable captured course identities in `removedCourseIds`, and `pendingSisuImport: null`. It carries no completion, so the callback's own course sets own the completion and a change another tab made while the reads waited is kept. An issue holds one name, a nullable code, one reason from `unresolved`, `module_not_placed`, `course_not_represented`, `no_official_match`, `ambiguous_official_match` or `version_choice_pending`, and optional transient candidates. The capture and PDF routes share the reason table in `web/src/features/structure/sisuImportWording.ts`. `SisuImportNotice` renders the item and reason, and the confirmation alone renders candidates.

## The PDF decoder and the pure extractor

`web/src/features/structure/sisuPdf.ts` is the lazy decoder. `ProfileTransfer.acceptFile` imports it only when the file's MIME type is `application/pdf` or its name ends in `.pdf`. The module imports `getDocument` and `GlobalWorkerOptions` from `pdfjs-dist` and the same-version worker URL from `pdfjs-dist/build/pdf.worker.min.mjs?url`, sets `workerSrc` to that bundled URL, reads the file's array buffer once, and reads the text layer of every page once. It never renders a page and never reads annotations, scripts, attachments or metadata. The loading task is destroyed in `finally` and on cancellation, and each page is cleaned up after its text is read. A decoder failure becomes `Invalid Sisu PDF plan`, so no source text reaches a diagnostic.

`web/src/features/structure/sisuPdfRows.ts` is the pure extractor. `extractSisuPdfRows(pages)` reads positioned text items only and imports neither PDF.js nor the network or storage. It keeps body text of at most 9 points with the supported print's baseline bounds, groups items by page and a 2-point baseline bucket, splits the left name and code column at x 200, and merges runs with a geometric word gap of a fifth of the greater text height. Continuation rows merge across wrapped lines and page breaks, ligatures and whitespace are normalized, and a joined hyphen keeps its compound without an added space. Code tokens need a digit, a dot or a hyphen unless the status cell proves a module heading. The FI and EN status forms identify modules, and a completion is the course row's date in the status column, never a module status or credit total.

## Served-data matching

`web/src/features/structure/sisuPdfMatch.ts` matches rows in the browser. `matchSisuPdfRows(rows, cache, signal)` reads the catalogue once through `readCachedCatalogue`, takes its dataset identity as the operation identity, and checks that identity during every structure batch read. Structure reads use `readCachedStudyStructures` with `allowUnavailable` and canonical known roots, first for the resolved programme roots and then in one additional batch when an added root or a sole selection recorded during the walk requires it. No request carries a code, name or row text, and no request is made per row.

Catalogue courses are indexed by exact code and modules by exact candidate code. A coded degree row becomes a programme only when its exact code names a catalogue module whose official type is `DegreeProgramme`. A course resolves by exact catalogue code, and several groups for one code are an ambiguous match. A module is matched by exact code, then exact FI or EN name, among the direct official children of its geometric parent candidates. Transparent rules and choices are flattened and the walk stops at a nested module.

`sameOfficialName` and `normalizeSisuName` in `web/src/features/structure/sisuNames.ts` own the name comparison, and `INDENT_TOLERANCE` in `sisuPdfRows.ts` is the one print indent tolerance. A coded module with no scoped match may join its captured parent only when its exact code names one catalogue group. One eligible version records `sisu_module_id`, and several leave `versionId` null. A module whose parent has several versions and whose own identity is unknown is kept as a null-identity item and reported as waiting for the version choice.

Unmatched rows stay in the plan as null-identity placeholders with their children, and each issue carries only a name, a nullable code, a reason and optional candidates. Candidates and issues are never written to the plan, profile, saved envelope, export or log. The returned typed plan carries an explicit duplicate non-null programme identity check, which raises `Invalid Sisu PDF plan` without a profile. `validateSisuPlan` is the untrusted stored-value and capture boundary.

## The pending import

`ProfileTransfer.tsx` keeps one local pending union: the `BrowserImport` values plus `{ kind: "sisu-pdf"; plan; issues }`. The PDF branch is neither a `BrowserImport` nor a persisted file variant. One `AbortController` covers the decode and the matching, so unmount aborts it and an aborted result is discarded without a late error. The same name field, programme list, reason list and confirmation serve the capture and the PDF. `confirm` prepares the profile with `prepareSisuProfile(plan, name, language)` and writes it through `store.importProfile`, or through `store.overwriteProfile` for the saved profile that already holds the name. The read batches already checked the dataset identity, and placement owns the uncoded module's later name match. Cancel, Escape and an outside dismissal clear the pending value and write nothing.

## Where a change belongs

- A change to what a downloaded capture holds, to how its markup is read, or to how pending choices are placed belongs in `web/src/features/structure/sisu.ts`.
- A change to the PDF decoder or its worker belongs in `web/src/features/structure/sisuPdf.ts`.
- A change to the supported print geometry or row rules belongs in `web/src/features/structure/sisuPdfRows.ts`.
- A change to catalogue or official-structure matching belongs in `web/src/features/structure/sisuPdfMatch.ts`.
- A change to a reason's text belongs in `web/src/features/structure/sisuImportWording.ts`.
